# Project Core Context & Architecture Blueprint

## 1. Hardware Environment
* **Host Machine:** MacBook Pro M5
* **Memory:** 24GB Unified Memory (High-bandwidth unified memory pool)
* **Execution Strategy:** High-precision local execution. Compute footprint optimized to stay within ~16GB active RAM, leaving an 8GB system buffer. Sequential execution model planned for ingestion vs. inference spaces if necessary.

## 2. Finalized Technical Stack
* **Layer 1: Ingestion & Parsing:** Chandra OCR 2 (5B Vision-Language Model). Outputs layout-preserved Markdown and structural data tables.
* **Layer 2: Embedding Engine:** Jina-Embeddings-v5-Omni-Small (Configured for Text, ~700M active parameters, native 32,768 token context window). 
* **Layer 3: Storage & Retrieval:** LanceDB (Embedded, serverless, disk-backed Apache Arrow columnar format). Dual-indexed with IVF-PQ (vector semantic) and Tantivy-based FTS (exact keyword/alphanumeric code matching) using Reciprocal Rank Fusion (RRF).
* **Layer 4: Synthesis Brain:** Qwen 3.5 9B Instruct (Running locally via high-precision quantization: Q5_K_M or Q8_0).

## 3. Core Architectural Decisions & Constraints
* **No Chunking:** Due to Jina v5's 32k context window, documents (multi-page medical files, full laboratory panels) are ingested as single, atomic, unbroken layout blocks.
* **No Reranker:** Eliminated from Phase 1. The small document retrieval count (due to large document blocks) combined with LanceDB's native RRF hybrid matching makes a local Cross-Encoder reranker computationally redundant and introduces unnecessary latency.
* **No Code Written Yet:** The project is strictly in the configuration and initialization phase. The tech stack is locked; implementation execution is the next immediate step.

## 4. Current Directive
Initialize the local database scheme, configure the Jina v5 embedding schema inside LanceDB, and establish the processing pipeline for the Chandra OCR 2 text output.
